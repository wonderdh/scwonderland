## 0. 한 문단 결론

프로젝트의 **기초 체력은 좋다** — `tsc`·`lint` 0건, `any` 0, FK 컨벤션 위반 0, Realtime 구독 관리·무거운 라이브러리 격리·open redirect 방어가 정석. 문제는 두 가지로 모인다. **(1)** `20260615110558_remote_schema.sql` 한 파일이 6월의 보안·정합성 패치 5종을 되돌린 채 4개월 넘게 운영에 남아 있고, 이번에 그 원복 범위가 알려진 것보다 넓다는 게 확인됐다(반 명부 SELECT 정책·출결→버스 트리거까지). **(2)** 리뷰가 세 번 쌓였지만 163건 중 14건만 고쳐졌고, 07-12 리뷰 이후 37 커밋 중 리뷰 항목을 처리한 커밋은 0건이다. 즉 "무엇을 고칠지" 는 이미 충분히 알고 있고, 부족한 건 **작은 묶음으로 바로 처리하는 것**이다. 아래 §1 의 5건은 합쳐서 반나절 분량이다.

**조치**: `on delete restrict` 로 교체 (삭제가 막히면 UI 에서 알게 됨) — 또는 반 탈퇴를 `is_active=false` soft delete 로. 둘 중 하나.

**조치**: `drop trigger … ; drop function …;` 2줄. 1-1 마이그레이션에 포함 가능.
