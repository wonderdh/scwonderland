# 숙제 검사 보드 (시리즈·레벨 기반) — 설계 스펙

- 작성일: 2026-05-29
- 브랜치: `feat/homework-check-board`
- 상태: 설계 승인됨 → 구현 계획(plan) 작성 대기

## 1. 문제 정의

교사가 숙제를 검사할 때 **반(class)을 먼저 찾아 들어가야** 한다. 현재 모바일(`m/homework`)·PC(`admin/homework`)
모두 반을 검색·요일·그룹·시간대·시리즈·레벨로 필터링해 특정 반을 고른 뒤, 그 반의 학생×책×유닛 그리드를
체크하는 구조다.

그러나 **실제 물리적 검사 흐름은 반 단위가 아니다**:

- 책 더미가 **시리즈 → 레벨 순서로** 정렬되어 도착한다.
- **같은 시리즈·같은 레벨을 여러 반이** 진행한다 (유닛 진도만 학생/반마다 다름).
- 책 표지에 **학생의 영어이름**이 적혀 있어 그것으로 학생을 식별한다.

즉 "앱은 반으로 진입을 강제하는데, 물리적 더미는 시리즈/레벨로 정렬"되는 **불일치**가 핵심 마찰점이다.
같은 시리즈·레벨을 여러 반이 하므로 "반 찾기"는 오히려 더 꼬인다.

## 2. 목표 / 비목표

### 목표
- 물리적 더미와 1:1로 맞는 **시리즈 → 레벨 → (반 무관) 학생 리스트** 진입 흐름 제공.
- 영어이름으로 학생을 **즉시 검색/점프**. 영어이름 중복 시 한글이름·반으로 구분.
- 학생을 고르면 **그 학생 책의 전체 유닛 그리드**를 보고 체크(기존 체크 경험 유지).
- 모바일·PC 모두 동등하게 잘 동작.

### 비목표 (이번 범위 아님)
- 책 표지 영어이름 **OCR/스캔** 입력 (추후 가속기로 검토 가능, 지금은 텍스트 검색).
- 숙제 진도/채점 **로직 자체 변경** (`getUnitSchedule`, status 모델, 결석 처리 그대로).
- 기존 **반 단위 체크 화면 제거** — 보조로 유지한다(아래 3장).
- 시리즈/교재 카탈로그 관리 화면 변경.

## 3. 진입 구조 / 화면 배치

새 **"숙제 검사 보드"**를 추가하고 이를 **기본 검사 화면**으로 둔다. 기존 반 단위 체크는
**보조 모드로 유지**(프로젝트 규칙: UI 기능 임의 축소 금지).

```
[시리즈 선택] → [레벨 선택] → [학생 리스트 (반 무관, 영어이름순)] → [학생 → 전체 유닛 그리드 체크]
                                     ↑ 영어이름 검색으로 즉시 점프
```

- **모바일** `src/app/(admin)/m/homework`:
  - 기본 모드 = 보드. 기존 "반 선택" 방식은 탭/토글로 남김.
- **PC** `src/app/(admin)/admin/homework`:
  - 기존 탭 구조에 **"보드" 탭 추가**하고 기본 탭으로. 기존 `tab=class`(반 단위) 탭은 유지.

## 4. 데이터 / 쿼리

기존 모델을 그대로 활용한다. 새 **read 서버 액션**을 추가하고, mutation은 기존 것을 재사용한다.

### 4.1 조인 경로
```
series(seriesId)
 └ homework_books (level 필터)
    └ class_homework_books      → class_id, homework_days, start_date, skip_dates
       └ student_homework_books → class_student → students(english_name, korean_name), classes(name)
          └ student_homework_progress (unit_number, status)
```

### 4.2 신규 서버 액션 (read)
`src/app/(admin)/admin/actions/homework-unit-actions.ts` 에 추가:

```ts
// 시리즈+레벨 단위로, 반에 상관없이 학생들의 진도를 조회
listSeriesLevelProgress(seriesId: string, level?: string) => {
  series: { id, name, totalUnits },
  students: Array<{
    studentId, englishName, koreanName,
    className, classId,            // 영어이름 중복 구분용
    studentHomeworkBookId,
    todayUnit: number | null,      // expectedDate == 오늘 인 유닛
    isAbsentToday: boolean,
    completedCount: number, totalUnits: number,
    units: Array<{ unitNumber, status, expectedDate }>   // 그리드용 (기존과 동일 형태)
  }>
}

// 상단 칩용: 활성 시리즈 + 각 시리즈의 distinct level 목록 (가벼운 쿼리)
listSeriesLevels() => Array<{ seriesId, seriesName, levels: string[] }>
```

- `todayUnit` / `expectedDate`: 기존 `getUnitSchedule()`(`src/lib/utils/homework-schedule.ts`) 재사용 →
  반마다 다른 유닛이 자연히 반영됨.
- `isAbsentToday`: 기존 `getAbsentStudentIds(today)` 재사용.
- **학생 정렬 기본값**: `englishName` 가나다(알파벳)순. (옵션: "반별 묶기" — 추후/토글)
- **인증**: read 액션은 `verifyTeacherOrAdmin`.

### 4.3 저장 (mutation)
- 기존 `bulkMarkUnits()` 그대로 재사용 (결석 자동 제외 옵션 포함). **새 mutation 불필요.**
- 셀 탭 시 단건 레코드로 호출(낙관적 업데이트 후 저장) — 기존 패턴과 일관.

## 5. 화면 구성 · 인터랙션

### 5.1 모바일 (아코디언)
학생 카드 탭 시 인라인으로 그 학생 전체 그리드를 펼친다. 오늘치 유닛을 강조.

```
┌─────────────────────────┐
│ 숙제검사        🔍 검색  │
│ 시리즈 [Starlight][Phon] │
│ 레벨   [L1][▸L2][L3]    │
├─────────────────────────┤
│ Starlight·L2     23명    │   ← 검색 시 영어이름 필터
│┌───────────────────────┐│
││Kevin  김민준 ·월수   ▾ ││   ← 탭하면 펼침
││오늘 U7   ▓▓▓▓░░ 6/10  ││
││┌─────────────────────┐││
│││U1 U2 U3 U4 U5 U6     │││   ✓=완료 ✗=미완 ·=대기
│││ ✓  ✓  ✓  ✓  ✓  ✓     │││
│││U7 U8 U9 U10          │││
│││[·]  ·  ·  ·          │││   ← 오늘치 U7 테두리 강조
││└─────────────────────┘││      셀 탭: 대기→완료→미완 순환
│├───────────────────────┤│
││Kevin  이서연 ·화목   ▸ ││   ← 결석이면 회색+결석뱃지
││오늘 U5   ▓▓░░░░ 3/10  ││
│└───────────────────────┘│
└─────────────────────────┘
```

### 5.2 PC (2-pane)
칩은 상단, 좌측 학생 리스트 + 우측 그리드 패널. 학생 간 빠른 이동.

```
┌────────────────────────────────────────────────────────┐
│ 숙제 검사   시리즈[Starlight▾] 레벨[L1][▸L2][L3]  🔍 kev │
├──────────────────────┬─────────────────────────────────┤
│ Starlight · L2  23명  │  Kevin  김민준  ·월수반          │
│ ▸ Kevin 김민준 ·월수  │  오늘 U7        완료 6/10         │
│   Kevin 이서연 ·화목  │  ┌────────────────────────────┐ │
│   Anna  박서윤 ·금요  │  │ U1 U2 U3 U4 U5 U6 U7 U8 U9..│ │
│   ...                 │  │ ✓  ✓  ✓  ✓  ✓  ✓ [·] ·  · │ │
│                       │  └────────────────────────────┘ │
│ (스크롤·검색 필터)     │  [◀ 이전 학생] [다음 학생 ▶]     │
└──────────────────────┴─────────────────────────────────┘
```

### 5.3 인터랙션 규칙
- **셀 탭** = 대기→완료→미완 순환. 낙관적 UI 업데이트 후 `bulkMarkUnits` 단건 저장.
- **오늘치 강조**: 카드의 "오늘 U7" 라벨 + 그리드의 해당 셀 테두리 강조 → 누를 곳이 한눈에.
- **검색**: 현재 선택된 시리즈·레벨 안에서 영어이름으로 필터(기본). 후보 카드에 한글이름·반 표시.
- **결석**: 카드 흐리게 + "결석" 뱃지. 셀은 막지 않되, 결석자에 완료 표시 시 가벼운 경고.

## 6. 컴포넌트 구조 (모바일·PC 로직 공유)

- `useHomeworkBoard` 훅 — 선택 시리즈/레벨/검색어 상태 + 데이터 로드 + 낙관적 업데이트.
- `SeriesLevelChips` — 시리즈·레벨 선택 칩.
- `BoardStudentList` — 학생 카드/행(영어+한글+반, 오늘치, 진도바, 결석).
- `StudentUnitGrid` — 기존 `src/components/homework/ClassUnitProgressList.tsx`의 셀 렌더링을
  추출/재사용. 모바일=아코디언 펼침, PC=우측 패널. **그리드 컴포넌트는 동일**.

> 기존 `ClassUnitProgressList`가 반-스코프 가정을 강하게 갖고 있으면, 셀 렌더링 부분만
> `StudentUnitGrid`로 분리해 보드/반 양쪽에서 공유한다(이번 작업 범위 내 타깃 리팩토).

## 7. 엣지 케이스

- **영어이름 없음**(`english_name` null): 한글이름을 주 표시로 fallback.
- **영어이름 중복**: 카드에 한글이름·반 항상 병기. 검색 결과도 동일.
- **한 학생이 같은 시리즈·레벨 책을 2권 이상** 보유: 책(=`student_homework_book`)별로 별도 행/그리드.
- **오늘 채점 대상 유닛 없음**(`todayUnit=null`): "오늘 없음" 표시, 그리드는 그대로 열람·체크 가능.
- **시리즈에 레벨이 1개뿐**: 레벨 칩 생략(또는 단일 칩).
- **결석자**: 진도 흐리게 + 뱃지. `bulkMarkUnits`의 결석 제외 옵션과 일관.

## 8. 에러 핸들링

- read 액션 실패: 보드에 인라인 에러 + 재시도. 빈 결과는 "해당 시리즈·레벨에 학생 없음" 안내.
- 셀 저장 실패: 낙관적 업데이트 롤백 + toast 에러(기존 toast 유틸 사용).
- 인증 실패: `verifyTeacherOrAdmin` 표준 경로.

## 9. 테스트

- **순수 함수**: 시리즈/레벨/학생 매핑·정렬(영어이름순), 오늘치 유닛 도출 로직을 순수 함수로 분리해 단위 테스트
  가능하게 한다(현재 레포는 테스트 인프라 없음 — 최소한 순수 함수 경계를 명확히 둬서 추후 도입 용이하게).
- **수동 검증 시나리오**:
  1. 시리즈→레벨 선택 시 여러 반 학생이 영어이름순으로 섞여 나온다.
  2. 영어이름 검색으로 중복 이름이 한글·반과 함께 구분되어 좁혀진다.
  3. 학생 펼침→오늘치 유닛이 강조되고, 셀 탭이 저장된다(새로고침 후 유지).
  4. 결석자 표시/제외가 동작한다.
  5. 모바일·PC 모두 동일 데이터로 동작한다.

## 10. 범위 요약 (단일 구현 계획용)

1. 신규 read 액션 2개(`listSeriesLevelProgress`, `listSeriesLevels`) + 순수 매핑 함수.
2. 보드 UI(모바일 아코디언 / PC 2-pane) + 공유 컴포넌트(`SeriesLevelChips`, `BoardStudentList`,
   `StudentUnitGrid`, `useHomeworkBoard`).
3. 모바일/PC 진입점에서 보드를 기본으로, 기존 반 단위 체크는 보조로 유지.
4. 저장은 기존 `bulkMarkUnits` 재사용.
